# Git 分支管理规范

本文档定义了项目的 Git 分支管理策略，用于规范代码开发、集成和发布流程。

---

## 1. 分支类型

| 分支 | 用途 | 生命周期 | 备注 |
|------|------|----------|------|
| `main` / `master` | 生产环境基准分支 | 永久 | 只能通过合并获得，禁止直接推送 |
| `uat` | 用户验收测试环境 | 永久 | 预发布环境，用于业务验收 |
| `st` | 系统测试环境 | 永久 | 集成测试环境，用于功能验证 |
| `dev` | 开发环境 | 永久 | 开发人员日常开发基准 |
| `T_XXX` | 特性分支 | 临时 | 开发完成后删除 |

---

## 2. 分支命名规范

### 2.1 特性分支

```
T_{特性名称}
```

**规则**：
- 以 `T_` 开头
- 特性名称使用全大写
- 多个单词使用下划线 `_` 分隔
- 简洁明了，体现功能含义

**示例**：

| 特性 | 分支名 |
|------|--------|
| 实时估值计算 | `T_REAL_CALC_VAL` |
| 用户认证 | `T_USER_AUTH` |
| 订单管理 | `T_ORDER_MGMT` |
| 支付功能 | `T_PAYMENT` |
| 报表导出 | `T_REPORT_EXPORT` |

### 2.2 其他分支

| 分支 | 命名 | 说明 |
|------|------|------|
| 开发分支 | `dev` | 开发环境基准分支 |
| 测试分支 | `st` | 系统测试环境基准分支 |
| 验收分支 | `uat` | 用户验收测试环境基准分支 |
| 发布分支 | `release/{version}` | 发布准备分支（可选） |
| 热修复分支 | `hotfix/{issue}` | 紧急修复分支（可选） |

## 3. 分支流程

### 3.1 特性分支生命周期

```
┌─────────────────────────────────────────────────────────────────┐
│                         分支流程图                                │
└─────────────────────────────────────────────────────────────────┘

┌─────────┐     ┌─────────┐     ┌─────────┐     ┌─────────┐
│  UAT    │◄────│   T    │     │   T    │     │   T    │
│ (基准)  │     │(开发中) │     │(开发中) │     │(开发中) │
└─────────┘     └────┬────┘     └────┬────┘     └────┬────┘
                     │               │               │
                     ▼               ▼               ▼
                ┌─────────┐     ┌─────────┐     ┌─────────┐
                │   DEV   │     │   ST    │     │   UAT   │
                │ (开发测试)│◄────│ (系统测试)│◄────│ (验收测试)│
                └─────────┘     └─────────┘     └─────────┘
```

### 3.2 分支拉取

**从 UAT 创建特性分支**：

```bash
# 1. 确保本地 UAT 分支是最新的
git checkout uat
git pull origin uat

# 2. 从 UAT 创建特性分支
git checkout -b T_REAL_CALC_VAL
```

### 3.3 开发流程

```bash
# 1. 在特性分支上开发
git checkout -b T_REAL_CALC_VAL
# 开发代码，提交...

# 2. 同步最新代码（从 UAT 拉取）
git fetch origin
git merge origin/uat
# 或使用 rebase
git rebase origin/uat
```

### 3.4 合并规范

特性分支开发完成后，需要按顺序合并到各环境：

```
T_XXX  ──►  DEV  ──►  ST  ──►  UAT  ──►  MAIN
```

| 阶段 | 合并目标 | 合并方式 | 触发动作 |
|------|----------|----------|----------|
| 1 | DEV | Merge Request | 自动部署到开发环境 |
| 2 | ST | Merge Request | 自动部署到测试环境 |
| 3 | UAT | Merge Request | 自动部署到验收环境 |
| 4 | MAIN | Merge Request | 发布到生产环境 |

## 4. Merge Request 规范

### 4.1 合并到 DEV

**源分支**：`T_XXX`  
**目标分支**：`dev`

**要求**：
- 代码通过本地测试
- 无重大缺陷

### 4.2 合并到 ST

**源分支**：`T_XXX`  
**目标分支**：`st`

**要求**：
- DEV 环境测试通过
- 单元测试覆盖率达标
- 代码审查通过

### 4.3 合并到 UAT

**源分支**：`T_XXX`  
**目标分支**：`uat`

**要求**：
- ST 环境测试通过
- 集成测试通过
- 产品经理验收通过

### 4.4 合并到 MAIN（发布）

**源分支**：`T_XXX` 或 `release/XXX`  
**目标分支**：`main`

**要求**：
- UAT 环境验收通过
- 发布审批通过

---

## 5. 分支保护规则

| 分支 | 保护规则 |
|------|----------|
| `main` | 必须通过 MR 合并，至少 1 人审批 |
| `uat` | 必须通过 MR 合并，至少 1 人审批 |
| `st` | 必须通过 MR 合并 |
| `dev` | 可直接推送（开发阶段） |
| `T_XXX` | 无限制（开发完成后清理） |

---

## 6. 分支清理

### 6.1 特性分支清理时机

- 合并到 UAT 并验证通过后
- 特性取消或过期时

### 6.2 清理命令

```bash
# 删除本地分支
git branch -d T_REAL_CALC_VAL

# 删除远程分支
git push origin --delete T_REAL_CALC_VAL

# 批量清理已合并的分支
git branch --merged uat | grep -v "uat" | xargs git branch -d
```

---

## 7. 冲突处理

### 7.1 解决冲突原则

1. **谁引入冲突，谁负责解决**
2. **优先保留目标分支的代码**（除非有特殊理由）
3. **重大冲突需要通知相关人员**

### 7.2 解决流程

```bash
# 1. 拉取目标分支
git fetch origin
git checkout T_REAL_CALC_VAL
git merge origin/uat

# 2. 解决冲突后提交
git add .
git commit -m "Merge: resolve conflicts with uat"

# 3. 继续开发或发起 MR
```

## 8. 常见问题

### Q1: 特性分支从哪个分支拉取？

**A**: 从 `uat` 拉取，确保特性分支包含最新的稳定代码。

### Q2: 开发过程中需要同步最新代码吗？

**A**: 建议定期同步，每天下班前执行 `git merge origin/uat` 或 `git rebase origin/uat`。

### Q3: 多个特性同时开发怎么办？

**A**: 每个特性创建独立的 `T_XXX` 分支，互不影响。

### Q4: 紧急修复怎么处理？

**A**: 从 `main` 创建 `hotfix/xxx` 分支，修复后依次合并到 `uat` → `st` → `dev` → `main`。

## 9. 命令速查表

```bash
# 创建特性分支
git checkout -b T_REAL_CALC_VAL

# 查看分支状态
git branch -a

# 拉取最新代码
git fetch origin
git merge origin/uat

# 推送代码
git push origin T_REAL_CALC_VAL

# 创建 Merge Request（GitLab）
glab mr create --source-branch T_REAL_CALC_VAL --target-branch dev

# 删除本地分支
git branch -d T_REAL_CALC_VAL
```

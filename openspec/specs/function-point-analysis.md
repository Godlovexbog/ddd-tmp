# 功能点计算规范

本文档定义功能点分析的标准方法，适用于项目规模估算和工作量评估。

---

## 1. 功能点分析方法概述

### 1.1 什么是功能点

功能点（Function Point，FP）是衡量软件功能规模的标准化单位，由 IBM 的 Alan Albrecht 于 1979 年提出。

**核心思想：** 从用户视角出发，衡量软件提供的业务价值，而非技术实现。

### 1.2 功能点的作用

- **规模估算**：评估项目大小
- **工作量估算**：估算开发所需人月
- ** productivity 度量**：衡量团队开发效率
- **成本估算**：基于规模计算项目成本

---

## 2. IFPUG 功能点计算方法

### 2.1 标准计算公式

```
功能点 = Σ(组件功能点) × 调整因子
调整因子 = 14 × (0.65 + Σ(系统特征评分 × 0.01))
```

### 2.2 完整计算步骤

```
步骤1: 识别和计数
    ├── 内部逻辑文件 (ILF)
    └── 外部接口文件 (EIF)

步骤2: 确定功能复杂度
    ├── 外部输入 (EI)
    ├── 外部输出 (EO)
    └── 外部查询 (EQ)

步骤3: 计算未调整功能点 (UFP)
    UFP = Σ(ILF×权重) + Σ(EIF×权重) + Σ(EI×权重) + Σ(EO×权重) + Σ(EQ×权重)

步骤4: 确定系统特征值 (TCF)
    TCF = 14 × (0.65 + Σ(14个系统特征评分 × 0.01))
    评分范围: 0-5 (0=不存在, 5=完全影响)

步骤5: 计算调整后功能点 (AFP)
    AFP = UFP × (TCF / 14)
```

### 2.3 复杂度权重表

#### 数据功能点（ILF/EIF）

| 复杂度 | DET | RET | FTR |
|--------|-----|-----|-----|
| 低 | 1-19 | 1 | 1 |
| 中 | 20-50 | 2-3 | 2-3 |
| 高 | >50 | >3 | >3 |

权重：
- 低复杂度：6 FP
- 中复杂度：10 FP
- 高复杂度：15 FP

#### 事务功能点（EI/EO/EQ）

| 复杂度 | DET | FTR |
|--------|-----|-----|
| 低 | 1-5 | 0-1 |
| 中 | 6-19 | 2-3 |
| 高 | >19 | >3 |

权重：
- 低复杂度：3 FP
- 中复杂度：4 FP
- 高复杂度：6 FP

## 3. 功能类型详细说明

### 3.1 内部逻辑文件（ILF）

**定义**：应用内部维护的一组逻辑相关数据，通过应用的外部输入进行维护。

**特征**：
- 数据由应用创建、更新、删除
- 数据存储在应用内部
- 对用户有业务意义

**示例**：
- t_valuation_record（估值记录表）
- t_transaction_record（交易记录表）
- t_cash_delivery_record（现金交付记录表）
- t_financial_product_delivery_record（金融产品交付记录表）

### 3.2 外部接口文件（EIF）

**定义**：应用引用的一组逻辑相关数据，由其他应用维护。

**特征**：
- 数据由外部系统维护
- 应用只进行查询操作
- 数据不存储在当前应用中

**示例**：
- 用户信息表（由用户模块维护）
- 角色信息表（由用户模块维护）

### 3.3 外部输入（EI）

**定义**：应用接收的来自用户或外部系统的数据或控制信息。

**特征**：
- 输入数据进入应用
- 可能包含对ILF的增删改操作
- 可能触发业务逻辑

**示例**：
- 创建估值记录（POST /api/valuation/record）
- 创建交易记录（POST /api/valuation/transaction）
- 创建交付记录（POST /api/valuation/delivery）
- 删除记录（DELETE /api/valuation/...）

### 3.4 外部输出（EO）

**定义**：应用向用户或外部系统输出的数据或控制信息。

**特征**：
- 输出包含衍生数据（计算、汇总）
- 包含对ILF的读取和运算
- 可能触发额外处理逻辑

**示例**：
- 计算实时估值（包含业务计算逻辑）

### 3.5 外部查询（EQ）

**定义**：应用向用户或外部系统输出的查询结果。

**特征**：
- 仅读取数据，不包含计算
- 不修改任何ILF
- 返回原始数据

**示例**：
- 按ID查询估值记录
- 按项目ID查询估值列表
- 按项目代码查询估值记录

### 4.3 未调整功能点（UFP）

```
UFP = 数据功能点(ILF) + 事务功能点(EI/EO/EQ)
    = 24 + 34
    = 58 FP
```

## 5. 系统特征调整

### 5.1 14个系统特征

| 序号 | 特征 | 说明 | 评分(0-5) |
|------|------|------|------------|
| 1 | 数据通信 | 数据传输方式 | 2 |
| 2 | 分布式处理 | 数据处理分布 | 1 |

| 5 | 事务率 | 事务处理频率 | 3 |
| 6 | 在线数据录入 | 交互式输入 | 3 |
| 7 | 终端用户效率 | 用户操作便捷性 | 2 |
| 8 | 在线更新 | 实时数据更新 | 2 |
| 9 | 复杂处理 | 业务逻辑复杂度 | 1 |
| 10 | 可复用性 | 代码复用程度 | 1 |
| 11 | 易于安装 | 部署便捷性 | 2 |
| 12 | 易于操作 | 运维便捷性 | 2 |
| 13 | 多场地 | 多环境部署 | 1 |
| 14 | 支持变更 | 变更响应能力 | 2 |

### 5.2 计算调整因子

```
Σ评分 = 2+1+2+1+3+3+2+2+1+1+2+2+1+2 = 25

TCF = 14 × (0.65 + 25 × 0.01)
    = 14 × 0.90
    = 12.6
```

---

## 6. 最终功能点

```
调整后功能点 = UFP × (TCF / 14)
             = 58 × (12.6 / 14)
             = 52 FP
```

## 7. 工作量估算

### 7.1 转换因子

| 基准 | 经验值 |
|------|--------|
| 1功能点 | 6-10小时 |

### 7.2 工期估算

```
总工时 = 52 FP × 8 小时/人天
      = 416 小时
      ≈ 52 人天（8小时/天）
```

考虑项目风险和缓冲：
```
预估工期 = 52 × 1.2 = 62 人天
```

按团队配置：
- 3人团队：约 21 天
- 5人团队：约 13 天

### 9.2 术语表

| 术语 | 说明 |
|------|------|
| ILF | Internal Logical File，内部逻辑文件 |
| EIF | External Interface File，外部接口文件 |

| EQ | External Query，外部查询 |
| DET | Data Element Type，数据元素类型 |
| RET | Record Element Type，记录元素类型 |
| FTR | File Type Referenced，引用的文件类型 |
| UFP | Unadjusted Function Point，未调整功能点 |
| AFP | Adjusted Function Point，调整后功能点 |
| TCF | Technical Complexity Factor，技术复杂度因子 |

### 9.2 复杂度判定快速参考

**数据功能复杂度判定：**

```
低复杂度：字段 ≤19 且 记录类型 ≤1 且 引用文件 ≤1
中复杂度：字段 20-50 或 记录类型 2-3 或 引用文件 2-3
高复杂度：字段 >50 或 记录类型 >3 或 引用文件 >3
```

**事务功能复杂度判定：**

```
低复杂度：数据元素 ≤5 且 引用文件 ≤1
中复杂度：数据元素 6-19 或 引用文件 2-3
高复杂度：数据元素 >19 或 引用文件 >3
```
